# Docker и CI

Из папки проекта в PowerShell:

```powershell
.\run-docker.ps1
```

Нужен запущенный Docker Desktop (Linux containers). Для AI нужна работающая на компьютере Ollama с моделями `qwen3:4b` и `qwen3-embedding:0.6b`. Модели не включены в образ. Первая сборка скачивает зависимости из интернета.

Открыть http://127.0.0.1:5180. FastAPI раздаёт собранный React и API с одного адреса. Это отдельная установка: прежние заявки с локального запуска автоматически сюда не переносятся.

## Что запускается

- Dockerfile собирает React, устанавливает Python-зависимости и создаёт образ приложения. Рабочий процесс запускается пользователем 10001 без root.
- Compose запускает PostgreSQL с pgvector, одноразовую подготовку ролей/таблиц и приложение. Приложение ждёт готовую БД и успешную подготовку.
- Индексация сохраняет 12 учебных фрагментов. Приложение использует отдельную роль чтения векторов.
- Volume `provider-support-stack_stack-data` хранит PostgreSQL отдельно от контейнера. Пересоздание контейнера сохраняет заявки, историю и векторы.
- Пароли генерируются один раз в `.local/docker-stack/stack.env`. Файл исключён из Git и образа. Сохраните его вместе с резервной копией базы: новые случайные пароли не заменят доступ к существующему volume.

Остановка с сохранением данных:

```powershell
.\run-docker.ps1 -Stop
```

Повторный запуск — та же команда без `-Stop`. Не удаляйте рабочий volume командой `down --volumes`.

## Проверки и CI

```powershell
.\check-docker.ps1
```

Скрипт создаёт отдельный проект Compose со случайным именем и отдельную тестовую БД. Собирает клиент, выполняет клиентские тесты и backend-тесты, затем удаляет только временные ресурсы этого тестового проекта. Рабочие базы не используются.

Workflow `.github/workflows/ci.yml` выполняет аналогичную проверку на Linux при push и pull request. Workflow запускается в публичном репозитории https://github.com/vitsgod/linia-ai-support. Актуальный результат смотрите на вкладке Actions.

В Linux CI используются `python3 scripts/compose_env.py --output <env-file>`, затем `docker compose --env-file <env-file> --profile tests build bootstrap tests` и `docker compose --env-file <env-file> --profile tests run --rm tests` с отдельным именем проекта. Для ручного запуска AI в Linux адрес Ollama задаётся через `STACK_OLLAMA_URL`: сервер модели должен быть доступен из контейнера. Windows-сценарий использует `host.docker.internal`.
