# Проверка качества после генерации

## Что изменилось

Раньше корректный JSON и существующий source_id позволяли показать совет, повторяющий уже выполненное действие. В сохранённом реальном примере пользователь написал «кабели проверены», а модель ответила «Проверьте, подключены ли сетевые кабели».

Теперь backend/answer_quality.py распознаёт некоторые явные формулировки двух выполненных действий: проверку кабелей и перезагрузку роутера. После генерации backend/rag.py проверяет, не предлагает ли ответ повторить их. При совпадении исходный текст не показывается: приложение возвращает mode=clarify, уточняющий вопрос об индикации/ошибке и пустой список источников. Повторного вызова модели нет. Уточнение формирует Python; оно не выдаётся за ответ из инструкций.

Цепочка: поиск → генерация → проверка формата/источников → проверка известных повторов → ответ или уточнение.

Примеры:

- «Кабели проверены» + «Проверьте кабели» → уточнение.
- «Я уже проверила кабель» + «Уточните, подключены ли кабели» → уточнение.
- «Роутер перезагружал» + «Перезапустите роутер» → уточнение.
- «Кабели ещё не проверял» не означает выполненную проверку: совет проверить их разрешён.
- «Перезагрузил ноутбук» не означает перезагрузку роутера.
- «Не перезагружайте роутер повторно» не считается предложением перезагрузки.
- Подтверждение «кабели уже проверены» само по себе не блокирует новый совет проверить индикацию.

Регулярные выражения работают с текстовыми формами, не понимают произвольную речь. Правила могут пропустить неизвестные формулировки или дать ложное срабатывание. Они не проверяют все возможные противоречия, медицинские/технические факты и обоснованность каждого предложения. Изменение модели/инструкций требует повторных измерений.

## Как оценивали

scripts/check_rag_quality.py запускает настоящие embedding-модель, PostgreSQL и Qwen3. Обёртка вокруг генератора только сохраняет исходный результат, не подменяет сетевые ответы. Отчёт docs/rag-quality-check.json содержит исходный текст модели, сработавшие проверки, конечный ответ и время.

Вместо одного признака «получен200» проверяются допустимый режим, отсутствие выбранных форм повторного совета, наличие источников у answer, отсутствие источников у clarify и ожидаемый документ. Три позитивных вопроса обязаны получить answer: случай одного устройства, ещё не выполненные проверки, данные для специалиста. Для описаний уже выполненных действий разрешён полезный ответ либо уточнение. Количество answer и clarify показывается отдельно: нельзя объявить систему хорошей только потому, что она на всё просит уточнение.

Критерии содержания в оценочном скрипте заданы отдельно от рабочего детектора. Они тоже ограничены: при ручном чтении обнаружили пропуск «Уточните, подключены ли кабели» и перечисление нескольких проверок через запятые; оба случая добавлены в регрессионные тесты. Набор использован при разработке и не является независимым измерением общей точности.

## Проверено 1 ноября 2026

- 53 теста backend прошли, включая 5 новых методов тестирования качества с несколькими примерами/контрпримерами. Зафиксированы ошибки до исправления, затем проверки прошли.
- Итоговые 10 реальных вопросов прошли выбранные критерии: 4 ответа, 6 уточнений. В двух случаях ответ модели содержал повтор проверки кабелей и был заменён уточнением.
- Итоговые ответы прочитаны вручную. Остались стилистические недостатки: модель иногда обращается к оператору («предложите») или упоминает id материала в тексте. Текущая проверка эти недостатки не исправляет; хорошая ссылка не гарантирует идеальную формулировку.
- API проекта перезапущен на8001. Два реальных POST после перезапуска вернули200: выполненные проверки не повторяются в проверенном ответе, ещё не выполненные — допускаются. Список заявок до/после совпал. Отчёт workspace/work/quality-http-check.json.
- UI, схема API и база заявок не менялись; frontend5173 использует обновлённый backend. Jobpilot8000 и PostgreSQL5432 не затронуты.

Запуск оценки из корня проекта при работающих локальных службах:

```powershell
.\.venv\Scripts\python.exe scripts/check_rag_quality.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Практика: сравнить ответы на «Интернет не работает, кабели проверены, роутер уже перезагружал» и «Интернет не работает, кабели ещё не проверял, роутер не перезагружал». Первый ответ может быть уточнением, второй может предложить невыполненные проверки. Результаты могут различаться между генерациями.
