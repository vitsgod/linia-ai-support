# Демонстрация на 5–7 минут

Подготовка: запустить Docker Desktop, Ollama с двумя моделями и `run-docker.ps1`. Открыть порт5180. Использовать только вымышленные сведения. Перед показом проверить доступность модели: первый ответ может быть медленнее из-за загрузки.

1. **Заявка.** Заполнить имя «Тестовый пользователь», тему «Не работает интернет» и описание. Нажать «Создать заявку», показать запись в списке. Объяснить: React отправляет POST, FastAPI проверяет данные, PostgreSQL сохраняет запись; GET загружает список.
2. **RAG.** Ввести «На телефоне интернет есть, а на ноутбуке нет». Запросить диагностику, открыть источник. Объяснить две модели: одна преобразует вопрос в вектор для поиска, другая получает найденный текст и составляет ответ. Точная формулировка ответа не фиксирована.
3. **Неуместный ввод.** Попробовать «321»: показать просьбу описать проблему словами. Это проверка формы ввода, а не доказательство полного понимания смысла сервером.
4. **Инструмент.** Выбрать Северный район, проверить аварии напрямую, затем через помощника с просьбой проверить выбранный район. Показать Южный: отсутствие данных означает unknown. Модель выбирает вызов, Python проверяет аргументы и читает учебный JSON.
5. **Черновик.** Ввести «По кабелю интернет работает, Wi-Fi не виден. Роутер уже перезагружал». Подготовить черновик, проверить факты, отредактировать. Перенести в форму и показать, что заявки ещё нет. Только отдельное нажатие создания сохраняет заявку.
6. **История.** Открыть журнал: диагностика, инструмент и черновик записаны отдельно от заявок. Обновить страницу. При наличии времени остановить и запустить Docker, показать сохранность данных в volume. История автоматически не передаётся модели.

Если модель недоступна, показать обработанную ошибку и сохранённый ввод; не представлять заранее записанный результат как живой ответ. Завершить ограничениями: учебные данные, нет авторизации, нет реального провайдера и гарантии правильности всех советов.
