# Локальные эмбеддинги: первый смысловой поиск

## Подтверждено

Установлена отдельная Qwen3-Embedding0.6B Q8_0, локальное имя `qwen3-embedding:0.6b`. Она возвращает вектор из1024чисел для текста через Ollama POST /api/embed. Для12наших фрагментов получены настоящие векторы. Генерирующая Qwen3 4B остаётся отдельной моделью и пока не получает результаты этого поиска.

Источник: официальный Qwen/Qwen3-Embedding-0.6B-GGUF, ревизия `370f27d7550e0def9b39c1f16d3fbaa13aa67728`, файл `Qwen3-Embedding-0.6B-Q8_0.gguf`, размер639150592байт. Проверенная SHA256:

```text
06507c7b42688469c4e7298b0a1e16deff06caf291cf0a5b278c308249c3e439
```

Исходный файл хранится в `.local/qwen3-embedding-0.6b-q8.gguf`, импортированные веса — в пользовательском хранилище Ollama. В Git они не входят. Импорт из папки проекта:

```powershell
& "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" create qwen3-embedding:0.6b --file models\Embedding.Modelfile
```

## Как проверить

```powershell
.\.venv\Scripts\python.exe scripts\search_knowledge.py --query "На телефоне интернет есть, а на ноутбуке нет"
```

Скрипт читает12фрагментов, отправляет их embedding-модели, отдельно получает вектор вопроса и вычисляет косинусную близость с каждым фрагментом. Возвращает три ближайших с названием и источником. К вопросу добавляется английская инструкция поиска по рекомендации авторов Qwen; текст документов остаётся без query-префикса.

Векторы нормализуются: их длина приводится к1. Это не меняет направление и позволяет сравнивать смысловую близость без влияния длины вектора. Каждый элемент не является отдельным понятным человеку признаком вроде «скорость интернета»: смысл закодирован совместно во всём векторе. Близость0.68 не означает68%вероятности правильного ответа.

## Результаты настоящей проверки

| Вопрос | Первый документ | Близость |
| --- | --- | --- |
| На телефоне интернет есть, а на ноутбуке нет | Одно устройство | 0.6832 |
| По кабелю работает, сеть Wi-Fi не видна | Не видна сеть Wi-Fi | 0.7513 |
| Какие данные передать специалисту | Передача обращения | 0.7200 |
| Интернет пропал на всех устройствах | Все устройства | 0.6637 |

Все4контрольных вопроса дали ожидаемый документ первым. На вопрос про борщ тоже нашёлся ближайший фрагмент, с близостью0.3181. Это показывает ограничение: поиск ближайшего соседа всегда выбирает что-то из непустой базы. Отказ при отсутствии подходящих материалов потребует отдельной проверки и калибровки; один пример не задаёт универсальный порог.

Полные результаты — semantic-search-check.json. Автотесты проверяют математику и некорректные ответы API; качество настоящей модели проверено отдельно на этих пяти примерах. Это небольшой smoke-набор, не доказательство качества на любых сообщениях.

## Где сейчас находятся данные

Полные векторы в этой демонстрации находятся в памяти Python и пересчитываются при каждом запуске. `.local/semantic-search-demo.json` хранит последний вопрос, образец восьми чисел его вектора и три результата с текстами. Это отчёт, а не постоянный индекс. PostgreSQL и таблица заявок не менялись. API и React пока не используют этот поиск.

Следующий шаг — постоянное хранение фрагментов и векторов в PostgreSQL с pgvector. В PostgreSQL18расширение отсутствует, native C++ инструменты не найдены. Docker установлен, но daemon не запущен. Проверенный Windows пакет conda-forge связан с PostgreSQL16, поэтому не устанавливался в18. Неподходящие бинарники не подменяли; общий кластер5432не меняли.

Источники: [модель Qwen](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF), [Ollama embed](https://docs.ollama.com/api/embed), [pgvector](https://github.com/pgvector/pgvector#windows).
