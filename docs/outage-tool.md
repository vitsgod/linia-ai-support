# Первый инструмент: учебный статус аварий

## Что сделали

backend/outages.py содержит `check_outage_status(area_code)` — обычную Python-функцию с узкой задачей. Она читает data/demo_outages.json, проверяет данные Pydantic и возвращает структурированный результат. Это полностью вымышленный локальный набор, не подключение к провайдеру.

GET /api/outages/{area_code} вызывает эту функцию. GET подходит для чтения: запрос не изменяет данные. React передаёт только код выбранного учебного района, показывает состояние ожидания, результат или ошибку. Текст описания, имя и тема для проверки не нужны.

| Район | Код | Результат |
|---|---|---|
| Учебный Северный | demo-north | active: зарегистрирован DEMO-OUTAGE-001, учебный обрыв связи |
| Учебный Центральный | demo-center | clear: в наборе аварий не зарегистрировано |
| Учебный Южный | demo-south | unknown: по району нет записи |

`clear` не доказывает исправность подключения. `unknown` не означает отсутствия аварии. Недоступный или повреждённый файл — отдельная ошибка503, а не clear/unknown. У неизвестного кода района —422, функция не вызывается. Время checked_at показывает момент чтения набора; это не время начала аварии и не обещание восстановления. Срок восстановления отсутствует и не выдумывается.

У active есть объект incident с id/title. У clear/unknown incident=null. Во всех успешных результатах demo=true. Пустое название, неверный статус, неизвестные поля или противоречие active/incident делают источник невалидным. Не публикуются путь файла и подробности исключения.

## Пример вызова

При работающем API проекта:

```powershell
Invoke-RestMethod http://127.0.0.1:8001/api/outages/demo-north
Invoke-RestMethod http://127.0.0.1:8001/api/outages/demo-center
Invoke-RestMethod http://127.0.0.1:8001/api/outages/demo-south
```

В http://127.0.0.1:5173/ под описанием проблемы появился блок «Учебный статус аварий». Выберите район и нажмите «Проверить аварии». После смены района старый результат очищается, запоздавший ответ старого запроса игнорируется. Повторное нажатие во время ожидания блокируется.

Кнопка имеет type=button: не отправляет форму заявки. Район сейчас не записывается в заявку. Ответы и ошибки инструмента хранятся только в состоянии React; после обновления страницы выбор начинается заново.

## Где здесь модель

На первом учебном шаге человек явно вызывал инструмент кнопкой «Проверить аварии». Этот прямой путь по-прежнему работает без Ollama. Затем добавлен отдельный модельный выбор функции: [model-tool.md](model-tool.md), кнопка «Проверить через помощника». Существующая RAG-диагностика работает отдельно.

Одношаговый выбор инструмента теперь проверен настоящим native tool_calls Qwen/Ollama. Наличие Python-функции само по себе не доказывает работоспособность модельного вызова; отдельные проверки описаны в model-tool.md. Полный агентный цикл, сохранение журнала и создание заявки здесь не реализованы.
